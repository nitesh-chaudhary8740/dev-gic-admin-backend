# Laravel 10 to Laravel 12 & PHP 8.4 Complete Upgrade Guide

---

## Executive Summary

Upgrading a legacy application from **Laravel 10** to **Laravel 12** while transitioning to **PHP 8.4** requires a structured, step-by-step methodology. Due to major breaking changes, strict type checking in modern PHP, and package deprecations, applying upgrades directly without preparing the local runtime and dependency tree often leads to fatal errors.

This guide details the exact process, troubleshooting strategies, local environment adjustments, and production deployment steps executed during a successful upgrade.

---

## Phase 0: Git Backup & Branching Strategy

Before making any system, runtime, or dependency updates, create a dedicated branch to isolate upgrade changes from the stable production codebase.

### Commands

```bash
# Ensure all current changes are staged and committed
git add .
git commit -m "Backup state prior to PHP 8.4 and Laravel 12 upgrade"

# Create and switch to the upgrade branch
git checkout -b upgrade-to-php84
```

> **WARNING: UNCOMMITTED CHANGES**  
> Do not attempt composer updates or PHP runtime changes with uncommitted work. Branching ensures a zero-friction rollback path if dependency resolution fails.

## Phase 1: Local Environment Setup (XAMPP & PHP 8.4)

Upgrading the framework requires running PHP 8.4 locally to allow Composer to resolve dependencies correctly.

### 1. PHP 8.4 Installation
1. Download the **PHP 8.4 VS16 x64 Thread Safe** zip package from [windows.php.net](https://windows.php.net/).
2. Navigate to your local XAMPP directory (`C:\xampp`).
3. Rename the existing PHP directory:
   - `C:\xampp\php` $\rightarrow$ `C:\xampp\php_old`
4. Create a new folder named `C:\xampp\php` and extract the PHP 8.4 package contents into it.
5. Copy `php.ini-development` to `php.ini`.

### 2. Configure `php.ini`
Open `C:\xampp\php\php.ini` and make the following critical adjustments:

Set the extension directory:
```ini
extension_dir = "C:/xampp/php/ext"
```

Enable required PHP extensions by removing the leading semicolon (`;`):
```ini
extension=curl
extension=fileinfo
extension=mbstring
extension=openssl
extension=pdo_mysql
extension=zip
```

### 3. Verify PHP Installation
Restart Apache and MySQL from the XAMPP Control Panel, then verify the PHP version via the CLI:
```bash
php -v
```
*Expected Output:* `PHP 8.4.x (cli) ...`

### 4. Resolving XAMPP Port Conflicts
If Apache or MySQL fails to start due to port binding conflicts (e.g., Windows System Process `PID 4` occupying port 80/443, or another MySQL service occupying 3306), reconfigure the ports:

* **Apache Configuration (`httpd.conf` & `httpd-ssl.conf`):**
  * Change `Listen 80` $\rightarrow$ `Listen 8080`
  * Change `Listen 443` $\rightarrow$ `Listen 4433`
* **MySQL Configuration (`my.ini`):**
  * Change `port=3306` $\rightarrow$ `port=3307`

> **PRO-TIP: DATABASE PORT SYNC**  
> If you change MySQL's port in XAMPP to `3307`, update your `.env` file accordingly:
> ```env
> DB_HOST=127.0.0.1
> DB_PORT=3307
> ```

## Phase 2: Composer Dependency Upgrade

To transition from Laravel 10 to Laravel 12, update core dependencies and replace abandoned or incompatible packages.

### Key Dependency Changes

1. **Abandonment of `blade-ui-kit/blade-ui-kit`:**  
   `blade-ui-kit` is unmaintained and locks `nesbot/carbon` to older versions incompatible with Laravel 12. It must be removed.
2. **Replacement of `laravelcollective/html`:**  
   `laravelcollective/html` is unmaintained. Replace it with `squipix/html` (`^1.0`), an actively maintained fork compatible with Laravel 12.
3. **Collision Compatibility:**  
   `nunomaduro/collision` `^7.0` is incompatible with Laravel 12. Upgrade to `^8.6`.

### Updated `composer.json` Configuration

Update your `composer.json` as follows:

```json
"require": {
    "php": "^8.4",
    "laravel/framework": "^12.0",
    "laravel/sanctum": "^4.0",
    "squipix/html": "^1.0"
},
"require-dev": {
    "nunomaduro/collision": "^8.6",
    "phpunit/phpunit": "^11.0",
    "spatie/laravel-ignition": "^2.10"
}
```

*Note: Ensure `"laravelcollective/html"` and `"blade-ui-kit/blade-ui-kit"` are completely removed from `"require"`.*

### Execute Upgrade Command

Run Composer with full dependency re-evaluation:

```bash
composer update --with-all-dependencies
```

## Phase 3: Application Code Modifications

After updating packages, adapt provider and alias registrations to match the replacement packages.

### Update `config/app.php`

#### 1. Register Service Provider
Add the `Squipix` HTML service provider to the `providers` array:

```php
'providers' => ServiceProvider::defaultProviders()->merge([
    /*
     * Package Service Providers...
     */
    Squipix\Html\HtmlServiceProvider::class,

    /*
     * Application Service Providers...
     */
    App\Providers\AppServiceProvider::class,
    App\Providers\AuthServiceProvider::class,
    // ...
])->toArray(),
```

#### 2. Register Class Aliases
Add the `Form` and `Html` facades to the `aliases` array:

```php
'aliases' => Facade::defaultAliases()->merge([
    // ...
    'Form' => Squipix\Html\FormFacade::class,
    'Html' => Squipix\Html\HtmlFacade::class,
])->toArray(),
```

#### 3. Clear Application Cache
Flush stale configuration and provider caches:

```bash
php artisan optimize:clear
```

## Phase 4: Database & Error Resolution (Troubleshooting)

### `.env` Database Setup

Ensure the local database configuration matches the runtime environment:

```env
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3307
DB_DATABASE=gicre_vigilance_new
DB_USERNAME=root
DB_PASSWORD=
```

### Common Errors Encountered & Solutions

#### Issue 1: `Call to undefined function mb_split()`
* **Cause:** The `mbstring` extension was either missing or disabled in `php.ini`.
* **Fix:** Open `C:\xampp\php\php.ini`, ensure `extension=mbstring` is uncommented, and restart Apache/CLI workers.

#### Issue 2: `Access denied for user 'root'@'localhost'` or `Unknown database`
* **Cause:** The application was attempting to connect to port `3306` (where a different or inactive MySQL service was listening) instead of the XAMPP MySQL port (`3307`).
* **Fix:**
  1. Test connectivity directly using XAMPP Shell:
     ```bash
     mysql -u root -P 3307
     ```
  2. Confirm the existence of `gicre_vigilance_new`.
  3. Force Laravel to re-read updated `.env` settings by clearing the config cache:
     ```bash
     php artisan config:clear
     ```

## Phase 5: Testing & Production Deployment

### 1. Local Testing Routine

Start the development server:

```bash
php artisan serve
```

* **Debugging:** Temporarily set `APP_DEBUG=true` in `.env` to catch any remaining PHP 8.4 deprecation notices or unhandled exceptions. Monitor logs directly via:
  ```bash
  tail -f storage/logs/laravel.log
  ```
* **Pre-Flight Check:** Ensure `APP_DEBUG=false` is restored before staging or committing changes for deployment.

### 2. Version Control Finalization

```bash
git add .
git commit -m "Complete upgrade to Laravel 12 and PHP 8.4 with dependency resolution"
git push origin upgrade-to-php84
```

### 3. Production Deployment (cPanel / Hosting Environment)

1. **PHP Version Configuration:**
   * Open cPanel and navigate to **MultiPHP Manager**.
   * Set the domain/subdomain PHP version to **PHP 8.4 (`ea-php84`)**.

2. **PHP INI Directives:**
   * Open **MultiPHP INI Editor**.
   * Increase limits to accommodate large file and PDF processing:
     ```ini
     upload_max_filesize = 32M
     post_max_size = 32M
     memory_limit = 256M
     ```

3. **Post-Deployment Commands:**
   Run the following commands on the server terminal or via deployment script:
   ```bash
   composer install --no-dev --optimize-autoloader
   php artisan migrate --force
   php artisan config:cache
   php artisan route:cache
   php artisan view:cache
   ```
